# - 工作流“智能体” vs 全自主智能体

字节扣子coze的企业版要下线了。

这说明第一代智能体已经开始退场了。

扣子曾经火过，那个时候，各种AI培训，直播，很多讲扣子的。
2025年，扣子还曾以19.3%的市场份额稳居中国智能体开发平台公有云市场第一。
但是怎么说呢？
方向错了。

扣子这种工作流的智能体，低代码平台，类似的还有n8n，dify等，太复杂了，每一步都要定义清楚，输入是什么，输出是什么。

这种工作流只能处理极其固定的任务，一旦处理稍微复杂一点的流程， 需要人工全部处理所有的可能性。这根本不现实。

什么时候需要这种所谓的“智能体”？就是在模型能力没这么强的时候。

比如一个任务，模型不能正确拆解步骤，10个步骤总会在关键的几个步骤中出错等等；这个时候需要利用人工编码的固定的代码块来约束。

然而随着模型的增强，自主的智能体犯错概率低了，规划的甚至比人考虑的更周到；且它可以自己快速迭代，泛化能力强，秒适配各种场景。

这个时候根本不需要人为来定义工作流的这种“智能体”了。

现在的这种工作流，已经被一个叫 “Skill”的技术替代。本质上也差不多。

扣子也曾经自己调整过，后面搞了扣子编程。
但是这种调整，太晚了，别的编程智能体已经占据了市场，内部还有trae竞争。

字节有钱，搞错一两个方向，是没有问题的。
我们幸好没有投入做扣子这种产品，连n8n这样的也没有投入。
我们要搞错一个方向，做错一个产品，就全军覆灭了。

可见，AI时代，看准方向是多么重要。

曾经本人也有类似的情况，内部一个以工作流处理任务的所谓的“Agent”，以及本人手搓的纯自主的Agent。

事实上差距明显，但不是所有人都能看出来。

但这种所谓的自主智能体= LLM + Harness，瓶颈很多。现在有一个现象，给一个**在该智能体能力范围之内**的任务时，他往往能完成的很好，比如coding，办公类；但一旦超出了能力范围，无论怎么调整都徒劳。
